# 입력 필드 디자인

승인: 2026-09-16. 기존 폰트를 유지하며 4px 모서리와 얇은 테두리를 사용한다.

- `packages/ui/src/text-field.css`: 입력창·여러 줄 입력·드롭다운의 공통 토큰과 스타일. `tokens.css`에서 모든 앱에 로드한다.
- 백오피스: 회색 기본/호버, 파란 포커스. 공개 화면: 밝은 배경 검정, 어두운 배경 흰색 호버/포커스.
- 드롭다운은 기본/호버/포커스/비활성만 표시한다. 선택 완료를 성공 상태로 보지 않는다. 필수 선택 검증은 그대로 유지한다.
- 텍스트 입력 오류는 실제 검증 상태(`aria-invalid` 또는 `:user-invalid`)에 연결한다. 단순 입력 여부로 성공을 표시하지 않는다.
- TextField의 `success`는 검증 완료를 명시할 때만 사용한다. SelectField에는 성공/오류 장식 속성이 없다.
- 기존 필드에도 공통 스타일이 적용되므로 새 이벤트·새 모듈이 개별 CSS 없이 같은 디자인을 사용한다.
- 체크박스·라디오·파일·색상·범위 선택과 버튼은 텍스트 필드의 외형 변경 대상에서 제외한다. 여러 줄 입력의 기존 높이와 크기 조정은 유지한다.
- 드롭다운 선택 목록 자체는 브라우저/모바일 기본 선택창을 사용하여 키보드와 모바일 조작을 유지한다.
- 검토용 화면 `/fields/index.html`은 로컬 preview 앱 전용이며 운영 Admin에 메뉴를 추가하지 않는다.

검증: 타입 검사, 110개 단위 테스트, production build. 로컬 PC/모바일에서 공개 입력과 편집 화면, 포커스 색상, 오류 상태, 드롭다운 선택을 확인한다.

## 2026-09-16 편집기·안내 모듈 후속 변경
- 편집기 좌우 패널은 독립 스크롤, 모듈 순서/삭제는 설정 상단.
- 안내 카드 추가/삭제/정렬. 기존 이벤트 안내의 제목/본문은 카드로 보존.
- 일정에 요일 표시. 동의·유의사항도 같은 컨테이너 배경/여백 사용.
- 동의 체크박스 24px, 항목 본문 모바일 12px/PC 14px (유의사항과 동일).
- 상세 원문이 없으면 자세히 보기 숨김. 필수 동의 체크 검증 유지.
- 공개 시 각 단계의 동의 버전을 자동 생성. 개인정보 동의 버전에 푸터 처리방침도 저장하여 변경 전 참여자의 원문을 보존. 단계 전환 시 상세 원문을 다시 입력하지 않음.
- 단계 준비는 공개된 푸터 처리방침 기준이며, 편집 중인 초안만 바꾼 경우 저장 후 공개가 필요함.
- 검증: 112개 단위 테스트, 기존 통합 시나리오 및 footer-consent-flow.mjs에서 빈 상세 원문으로 전체 사이클 통과.

## 기본 입력 항목 편집·선택 동의
- 입력창 모듈의 기본/추가 항목을 같은 편집기에서 관리한다. 순서·유형·레이블·글자 제한·플레이스홀더·도움말을 저장한다. 빈 도움말은 표시하지 않는다.
- 이름/문구/연락처/이메일/인스타그램의 저장 연결은 고정한다. 연락처 유형은 연락처/텍스트/숫자, 이메일은 이메일/텍스트, 인스타그램은 ID/텍스트 중 선택한다. 실제 연락처·이메일·계정 형식 검증 및 중복 투표 검증은 유지한다.
- 인스타그램 입력의 @는 고정 접두사이며 입력값/암호화 저장/중복 비교에는 포함하지 않는다. 붙여넣은 앞쪽 @도 제거한다.
- 입력 정의가 없는 기존 이벤트는 기존 필드를 기본값으로 구성한다. 수정하여 저장할 때 inputFields에 명시적으로 기록한다.
- 입력한 문구 제한은 서버 단계 제한에도 반영한다. 추가 입력값은 기존처럼 개인정보와 함께 암호화한다.
- 동의 항목의 필수/선택은 모든 항목별 지정 가능. 설정이 없는 이전 항목은 필수로 유지한다. 필수 여부 변경도 동의 버전을 새로 만들고 서버 stage_policies.required와 함께 저장한다. 선택 항목은 체크한 경우에만 참여자의 동의 이력이 생성된다.
- 검증: 116개 단위 테스트, editable-inputs-flow.mjs 전체 API 사이클, editable-inputs-ui.mjs 편집/저장/공개/필수 여부/인스타그램/모바일 확인.

## 기본 항목의 선택 입력과 개인정보 표시
- 기본 입력 항목도 필수/선택 설정 가능. 선택 항목은 레이블 옆 '(선택)' 표시, 빈 입력 허용. 입력값이 있을 때에는 기존 형식·길이 검증 유지.
- 선택 항목의 빈 값은 빈 값으로 암호화 저장하고 마스킹에도 가짜 이름·별표를 만들지 않는다. 투표 중복 확인은 실제 값이 있는 식별 정보만 해시 처리한다. 모두 선택으로 설정하면 정보 미입력 투표를 대조할 수 없음을 편집기에 안내한다.
- 개인정보 목록은 이벤트 전체의 실제 마스킹 데이터 기준으로 값이 있는 열만 반환한다. 페이지를 이동해도 열이 바뀌지 않는다. 새 투표 참여자에게 가상 이름을 부여하지 않는다.
- 원문 보기는 빈 항목/빈 추가 객체를 숨기고 실제 추가 항목은 레이블과 함께 따로 표시한다. 긴 값은 줄바꿈하며 모바일은 항목명/값을 세로 배치한다.
- 검증: 119 단위 테스트, optional-fields-flow 및 기존 전체 통합 시나리오, privacy-layout-ui PC/모바일 확인.
