# Admin 구조·편집 기능 개편안

2026-09-15 · 계획 검토 대기. 기존 운영 데이터 변경이나 배포 없이 코드 구조를 확인했다.

## 확인된 문제

- `apps/admin/src/events/AdminPreview.tsx`: 상단 헤더와 별도 운영 진입 방식으로 탐색이 분리돼 있다. 추가 입력 항목 편집 코드가 두 번 중복되어 있다. 단계 추가 기능은 단계 구성의 접힌 영역 안에 있으며 빠진 기본 단계만 추가하는 방식이다.
- `apps/admin/src/events/EventOperations.tsx`: 공개·일정·동의·심사·후보·개인정보·기록·초기화가 한 화면에 연속 배치된다.
- `packages/event-builder/src/model.ts`, `validation.ts`: 추가 입력만 설정 모델에 포함된다. 기본 입력 항목의 표시명·안내문·순서가 통합 설정으로 정의되지 않았다.
- `workers/public/src/events/index.ts`: 기본 개인정보 검증과 추가 입력 검증이 별개다. 단순히 입력 요소만 수정하면 저장·검증과 어긋날 수 있다.
- `workers/data/src/events/repository.ts`: 동의 종류가 privacy/work-license로 제한돼 있다. 자유로운 항목 추가·삭제에는 버전 및 연결 구조 확장이 필요하다.

## 왼쪽 메뉴와 화면 구분

상단의 서울아레나 / Events / FIRST SEAT 및 관리자 헤더를 제거한다. 아래 메뉴는 콘텐츠 편집·운영 어디에서도 유지한다. 각 화면은 주소를 가지며 새로고침·뒤로가기·직접 진입을 지원한다. 저장하지 않은 변경이 있을 때만 이동 확인을 제공한다.

- 대시보드: 전체 이벤트 현황, 이벤트 생성
- 이벤트
  - FIRST SEAT (다른 이벤트도 동일)
    - 콘텐츠 편집
    - 운영
      - 공개·일정: 현재/다음 단계, 공개 여부, 접수 상태, 일정
      - 응모작 심사
      - 후보·투표: 후보 편집·확정과 득표 현황
      - 결과 선정
      - 개인정보
      - 운영 기록
      - 설정: 복제·보관·테스트 데이터 초기화

동의문은 콘텐츠 편집의 개인정보 동의 모듈에서 직접 관리하며 운영 화면에 별도 편집 원문을 두지 않는다. 같은 설정을 두 군데에서 따로 저장하지 않는다.

## 단계 편집

항상 보이는 ‘단계 추가’ 버튼에서 공모·투표·결과를 선택한다. 삭제한 단계도 다시 추가할 수 있다. 초기는 각 종류 한 개까지 지원하며 동일 종류 반복 단계는 이번 범위에 넣지 않는다. 제외는 데이터 삭제가 아니라 구성에서 숨기는 처리로 바꾸고, 다시 넣으면 문구·모듈 구성을 복원한다. 현재 접수 중인 단계는 직접 제외하지 않고 먼저 접수를 중지하고 다른 단계를 선택하도록 안내한다. 이미 모인 응모·투표·동의 이력은 보존한다.

## 미리보기와 정렬

공개 이벤트의 제목·소개·본문·이미지·결과 문구는 가운데 정렬을 기본으로 한다. 입력상자·선택상자·동의 체크박스·목록은 열 너비를 채우고 읽기 편한 왼쪽 정렬을 유지한다. 관리자 설정 항목·표 자체를 가운데 정렬하지 않는다.

편집 중인 모듈은 편집용 미리보기에서 파란 점선과 모듈 이름으로 표시한다. 미리보기 모듈을 클릭하면 해당 설정을 연다. 점선은 실제 공개 페이지에 노출하지 않는다. 초점 표시와 선택 표시를 구분한다.

사진의 추가 입력 설정은 중복 렌더링을 제거하고 공통 필드 컴포넌트로 통일한다. 체크박스는 가로 배치, 라벨·입력·도움말은 일정한 간격, 좁은 열에서 줄바꿈과 최소 너비를 보장한다.

## 기본·추가 입력 통합

문구·이름·연락처·이메일·인스타그램과 추가 항목을 하나의 순서 목록으로 편집한다. 표시 이름, 입력 전 회색 안내문, 도움말, 순서를 수정한다. 추가 항목은 추가·삭제하며 가능한 항목은 필수 여부도 설정한다.

내부 저장 키와 화면 이름을 분리해 ‘연락처’를 다른 표시명으로 바꿔도 연락처 검증·암호화·중복 대조가 유지되게 한다. 공모 문구와 중복 투표 제한에 필요한 기본 식별 항목은 필요한 역할을 유지하며, 삭제 제한이 있으면 이유를 해당 항목에 표시한다. 기본 식별 기능 자체의 제거는 이번 요청에 포함하지 않는다.

서버는 저장된 설정을 기준으로 필수·형식·글자 수를 검증한다. 기존 이벤트는 기존 기본 입력 항목을 기본값으로 읽어 호환성을 유지한다. 추가 항목도 표시명 변경이나 재정렬로 과거 데이터 연결이 끊어지지 않도록 고정 ID를 사용한다.

## 동의 항목 편집

동의 모듈에서 체크박스 문구·자세히 보기 원문·필수/선택·순서를 편집하고 항목을 추가·제외한다. 개인정보 수집에 필요한 기본 동의는 개인정보 입력이 있는 동안 유지한다. 항목 제외는 이후 참여 화면에서만 제외하며 이전 원문·동의 이력을 삭제하지 않는다.

각 항목에 고정 ID와 버전을 부여한다. 변경 시 새 버전을 저장하고, 실제 공개에 적용된 버전을 기준으로 서버에서 제출한 동의 목록을 검사한다. 선택 동의는 미체크도 구분해 기록한다. 과거 privacy/work-license 데이터는 기존 ID와 원문을 보존하며 새 편집 모델에 연결한다. 새 스키마가 필요하면 추가 방식의 마이그레이션만 적용한다.

## 구현·검증 순서

1. 왼쪽 메뉴·운영 하위 화면·공통 편집 필드·선택 모듈 점선·정렬을 대표 화면으로 구현해 로컬 PC/모바일 검토.
2. 검토 후 기본 입력 설정·동의 버전 모델 및 서버 검증 연결.
3. 단계 제외/복원, 직접 URL 이동, 미저장 변경, 기본/추가 항목 저장과 재정렬, 이전 동의 이력 보존을 테스트.
4. 가상 이벤트에서 공모→심사→투표→결과 및 이벤트 간 분리 검증. 실제 참여 데이터 초기화는 수행하지 않음.
5. 승인된 범위 배포 후 실제 관리자 경로와 동작 확인.

첫 화면 검토 때는 구현한 범위와 아직 연결하지 않은 기능을 구분한다. 원본 FIRST SEAT 서비스는 변경하지 않는다. 추가 유료 서비스나 라이브러리 도입은 필요하지 않다.
