# 이벤트 모니터링과 공개 캐시

## 운영 화면
운영 > 모니터링에서 한국시간 기준 최근 24시간(시간별), 30일(일별), 12주(월요일 시작 주간별)를 선택한다. 페이지 조회수·응모 현황·투표 현황 그래프는 독립되어 있으며 응모/투표 단계 상태를 표시한다. 그래프 선택 또는 수치 표에서 값을 확인한다. 새로고침은 수동이다.

페이지 조회는 공개 화면이 처음 표시될 때 문서당 1회 전송한다. 새로고침은 새로운 문서로 집계하고, 자동 상태 재조회·관리자 편집기 미리보기는 집계하지 않는다. 임의 UUID는 문서 요청 중복 제외에만 쓰며 개인 정보·IP·지속 방문자 ID를 저장하지 않는다. 브라우저 차단/네트워크 실패나 자동화된 방문 때문에 완전한 실사용자 수를 뜻하지 않는다. 첫 계측 이전 조회수는 미수집으로 표시한다.

응모/투표는 기존 저장 레코드의 접수 시각으로 별도 집계한다. 현재 구간은 일부 시간만 포함된다. 초기화/삭제된 기록은 집계에서도 제외된다. 페이지 조회수 집계는 이벤트 삭제 시 함께 제거되며 접수 데이터 초기화와는 별개로 유지된다.

급증 알림은 마지막으로 완료된 15분의 조회수가 100회 이상이고, 그 직전 완료된 15분 대비 3배 이상일 때 표시한다. 이전 구간이 0이면 배율 경보를 만들지 않는다. 두 비교 구간 전체가 수집된 후 적용한다. 이는 화면 내 안내이며 메일/문자 알림이나 공격 판정, 인프라 요금제 사용량 알림이 아니다.

## 최적화
- 공개 HTML에 공개 중인 단계 데이터만 안전하게 포함해 브라우저의 중복 초기 조회를 없앤다.
- 20초 전체 조회를 약 60~65초 상태 조회로 교체. 상태 SQL은 1개이며 revision 변경 때에만 전체 콘텐츠를 요청한다.
- 숨김 탭에서는 중지, 다시 보이면 즉시 확인. 예정된 시작·종료 시각은 로컬 타이머도 반영한다. 입력 중 다른 단계/회차로 바뀌면 현재 입력을 버리지 않고 접수를 중지한다.
- Vercel 공유 CDN: 공개 HTML/콘텐츠 15초, 상태5초, 이미지60초. 브라우저는 재검증. 오류·개인정보·관리자·접수·투표·조회수기록 응답은 no-store. 오래된 오류 응답 대체 제공 없음.
- 콘텐츠 수정/비공개/삭제 직후 캐시가 최대 각 TTL만큼 남을 수 있다. 열린 화면의 내용 변경은 다음 상태 조회에 반영된다. POST 접수 검증은 캐시를 전혀 사용하지 않고 DB의 현재 단계·일정·중복 조건을 검사한다.
- 공개 이미지 DB조회는 현재 공개단계 이미지인지 검증한 후 읽는 2개 쿼리로 축소.

## 데이터 및 배포
0006_monitoring.sql은 새 익명 계측 테이블3개와 인덱스/트리거만 추가한다. 기존 참여 레코드는 수정하지 않는다. 방문 재전송은 PK로 중복 제외, 신규영수증과 15분카운터 증가는 하나의 원자적 SQL/트리거로 처리된다. 영수증24시간, 집계90일 보관; 기존15분 정리작업에서 만료분 삭제. 보고기간은 최대84일이다.

순서: 새 테이블 추가 → Data → Public/Admin Workers → 화면 GitHub/Vercel 배포. 초기화된 모든 이벤트의 계측 시작시각은 마이그레이션 실행시각이며 신규이벤트는 생성시각이다. 앱 롤백 시 추가 테이블은 남겨도 기존 앱에 영향 없음.

검증: 한국시간 경계, 주간 경계, 알림 최소기준, 페이지뷰 중복·이벤트격리·삭제연쇄, 응모/투표 별도 집계, 캐시 허용목록과 비공개 캐시 금지, HTML JSON 주입 안전성 단위 테스트. 로컬 Workers/D1 실제 접수·심사·투표·결과 및 모니터링 통합 검증. 브라우저 PC/모바일과 시간제어 폴링 검증.
