# 팔로워 자료 대조 및 가중 추첨

## 범위

운영 > 개인정보 > 투표자 탭에서만 팔로워 자료 업로드 및 가중 추첨을 제공한다. 공모자 일반 추첨은 유지한다. 전체 투표자가 대상이며 인스타그램 미입력자는 미확인/기본 1배이다. 같은 사람의 별도 참여 기록을 합치는 기능은 없으며 기존 참여 레코드 단위로 추첨한다. 과거 당첨자는 다음 추첨에서 제외하지 않는다.

## 자료 및 보안

- 계정 센터에서 @seoularena.official의 팔로워 및 팔로잉, 전체 기간, JSON으로 내보낸 ZIP을 선택/드롭한다.
- ZIP은 브라우저에서 처리한다. followers 또는 followers_N.json만 읽고 다른 자료는 전송하지 않는다.
- 최대 ZIP 합계 50MB, 100,000개 계정. 압축 해제 크기 제한, CRC 검사, ID 형식 검증을 적용한다. 비정상 파일은 기존 자료를 교체하지 않는다.
- 파일명 날짜는 참고용이며 `(파일명 기준)`으로 표시한다. 개별 관계 timestamp와 ZIP 수정 시간을 내보내기 생성 시각으로 간주하지 않는다. 업로드 시각은 서버가 기록한다.
- 계정명은 인증된 관리자 API로 500개씩 전송한 뒤 기존 투표 식별 HMAC과 같은 키·이벤트·단계·회차로 해시하여 저장한다. ZIP, 원본 계정명, 개인 예시 파일은 DB/저장소/로그에 보관하지 않는다.
- 업로드는 운영자·이벤트에 귀속된다. 청크 재시도는 동일 내용만 허용한다. 완료 전에는 기존 자료가 유지되고 완료 시 원자적으로 교체한다. 중간에 다른 운영자가 자료를 교체하면 재시도를 요구한다.
- 투표자 조회와 추첨 시 최신 스냅샷을 기존 Instagram identity HMAC에 조인한다. 따라서 기존/신규 투표 모두 동일하게 판정한다. 공개 API에는 팔로워 데이터가 노출되지 않는다.
- 실제 계정 소유/실시간 팔로우를 검증하는 기능이 아니다. 자료 목록 일치 여부이며 잘못된 계정의 ZIP도 인식할 수 있으므로 공식 계정 자료 선택이 필요하다.
- 이벤트 삭제/회차 초기화 시 자료를 삭제한다. 새 적용 시 이전 자료를 삭제한다. 미완료 업로드는 24시간 후 기존 정리 작업에서 삭제한다.

## 추첨

1~100배, 소수점 한 자리까지 허용한다. 팔로우 중은 입력 배수, 나머지는 1배. 서버 crypto 난수의 rejection sampling과 정수 가중치로 순차 비복원 추출한다. 한 번의 추첨에서 같은 레코드는 두 번 나오지 않는다. 클라이언트가 표시한 자료 ID가 서버와 다르면 추첨하지 않고 새로고침한다.

## 배포 시 필수 순서 (이번 작업은 커밋만 수행)

1. Admin Worker에 **현재 Public Worker와 동일한** `IDENTITY_HMAC_KEY` 비밀값을 설정한다. 새 키를 생성하거나 기존 공개 키를 교체하지 않는다. 잘못된 키는 기존 투표자와 일치하지 않는다.
2. D1 migration `0007_followers.sql` 적용.
3. Data Worker, Admin Worker 배포.
4. 프론트엔드 배포. Git push는 Vercel 자동 배포를 유발할 수 있으므로 승인 없이 수행하지 않는다.
5. 가상 검증 이벤트에서 자료 적용과 판정 확인 후 실제 이벤트 자료를 등록한다.

로컬 키 생성 스크립트는 새 환경에서 public/admin에 같은 HMAC 키를 저장한다. 기존 로컬 환경은 비밀값을 노출하지 않고 admin에 기존 public 키를 추가한다.

## 검증

단위 테스트: ZIP 분할/중복/손상/빈 목록, HMAC 일치, 신규 투표자, 원자 교체, 타 운영자·이벤트 차단, 오래된 자료 추첨 차단, 회차 초기화·삭제, 가중치 구간 및 중복 선정 방지.
브라우저 통합 테스트: `tests/platform/browser-followers.mjs`는 분리된 로컬 테스트 이벤트/API를 환경 변수로 받아 실제 컴포넌트와 Worker/D1을 검증한다. 운영 API는 사용하지 않는다.
